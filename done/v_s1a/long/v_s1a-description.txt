TITLE
My AI Removed One Form Field. It Never Mentioned the Price

DESCRIPTION
I asked my AI to remove one question from a booking form: "Do you have pets?" It did exactly that, and it even warned me that cat-allergic cleaners could now be sent to homes with pets. It never mentioned the $15 pet fee, because the fee is calculated by a trigger in the database, and the AI couldn't see the database.

Then I gave it read access and asked again. It went further, and made a business decision about my staff's work without asking. The price was still wrong.

"Remove the question" is four changes: stop asking, stop saving, stop using it, and decide what happens to the answers you already have. Here's how to do it in order, and how to check what your AI can't see.

git grep -n -i -E "has_?pets|haspets"

PROMPT 2: THE BLAST-RADIUS QUERY (Supabase SQL editor, read-only)
Change 'bookings' and 'has_pets' to your table and column.

-- views that use the column (tracked by Postgres)
select 'view' as kind, view_schema::text as schema, view_name::text as name
from information_schema.view_column_usage
where table_schema = 'public' and table_name = 'bookings' and column_name = 'has_pets'

union all

-- functions whose body mentions it (bodies are NOT dependency-tracked, so search the text)
select 'function', n.nspname::text, p.proname::text
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where p.prosrc ilike '%has_pets%'
  and n.nspname not in ('pg_catalog', 'information_schema')

union all

-- RLS policies whose expressions mention it
select 'policy', schemaname::text, (tablename || '.' || policyname)::text
from pg_policies
where qual ilike '%has_pets%' or with_check ilike '%has_pets%'

union all

-- every user trigger on the table (check what each function does)
select 'trigger on bookings', 'public', (t.tgname || ' → ' || t.tgfoid::regproc::text)
from pg_trigger t
where t.tgrelid = 'public.bookings'::regclass and not t.tgisinternal

order by 1, 3;

-- Also check by hand: has_pets values now in the table (look for a new null group)

PROMPT 3: MAKE IT SAFE
We're removing the "[question]" question from the form. Existing records keep their value. New records store null, which means "unknown", not "no". Before removing the input, update every place that reads `[column]` so that null shows "Unknown", is flagged for a person to confirm, and never gets the "no" behaviour automatically. Then remove the input. Don't drop the column. Show me each change.
